# Web Interface Guidelines (UX チェックリスト)

React component (`.tsx`/`.jsx`) を実装・変更・レビューする時の UX 基準。
出典: [Vercel Web Interface Guidelines](https://vercel.com/design/guidelines)。

差分に関係する項目だけを満たす。全項目を機械的に列挙しない。迷ったら出典の原文を確認する。

## Interactions / 操作

- [ ] フローがキーボードで完結する (WAI-ARIA Authoring Patterns に従う)
- [ ] フォーカス可能要素に可視フォーカスリング (`:focus-visible` を優先し、ポインタ操作時の不要な表示を避ける)
- [ ] ヒット領域は最小 24px・モバイル 44px、視覚サイズと一致
- [ ] **状態を URL に持たせる** — フィルタ・タブ・ページネーション・展開状態を deep-link 可能にし、リロード/共有/戻る進むを効かせる。URL state ライブラリ (例: nuqs) を使い、履歴は replace、高頻度更新は throttle で間引く。モーダル開閉・入力途中・未保存ドラフトは URL に入れない
- [ ] 楽観的更新は即時反映し、サーバー応答で整合を取る
- [ ] 破壊的操作は確認ダイアログ or Undo (安全な取り消し猶予) を提供
- [ ] ナビゲーションは `<a>`/`<Link>`、操作は `<button>` (div で代替しない)
- [ ] トースト・インラインバリデーションは `aria-live="polite"`
- [ ] スピナーは 150-300ms の表示遅延 + 300-500ms の最低表示時間 (チラつき防止)
- [ ] モバイルの入力 font-size ≥ 16px (オートズーム防止)、ブラウザズームを無効化しない

## Forms / フォーム

- [ ] 全コントロールに `<label>` (クリックで対応コントロールにフォーカス)
- [ ] 送信ボタンはリクエスト開始まで有効、開始後に disable
- [ ] エラーはフィールドの隣に出し、送信時は最初のエラーへフォーカス
- [ ] `autocomplete` と意味のある `name` を設定 (autofill 有効化)
- [ ] 用途に合った `type`/`inputmode` (適切なキーボード・検証)
- [ ] `<input>`/`<textarea>` で paste を禁止しない
- [ ] 入力値は trim する。データ消失の恐れがある離脱は警告

## Content / コンテンツ・a11y

- [ ] 数値の縦比較は `font-variant-numeric: tabular-nums`
- [ ] 色だけに意味を持たせない (テキストラベルを併記)
- [ ] アイコンのみのボタンに `aria-label`
- [ ] ネイティブ要素 (`button`/`a`/`label`/`table`) を `aria-*` より優先
- [ ] 空・疎・密・エラーの全状態をデザインし、各画面に次の一手/回復導線を用意
- [ ] スケルトンは最終内容と一致させ、レイアウトシフトを防ぐ
- [ ] `<title>` が現在のコンテキストを反映
- [ ] 日付・数値・通貨をユーザーのロケールに合わせる

## Animations / アニメーション

- [ ] `prefers-reduced-motion` の代替を用意
- [ ] GPU 加速プロパティ (`transform`/`opacity`) を優先
- [ ] `transition: all` 禁止 — アニメーション対象を明示列挙
- [ ] ユーザー操作で中断可能。自動再生でなく操作に応答して動かす

## Layout / レイアウト

- [ ] モバイル・ラップトップ・ウルトラワイドで崩れない
- [ ] safe-area (ノッチ/インセット) を変数で考慮
- [ ] JS での寸法計測より flex/grid/intrinsic レイアウトを優先

## Performance / パフォーマンス

- [ ] 再レンダリングを最小化し、軽く保つ
- [ ] 大きいリストは仮想化 (`content-visibility` / `contain-intrinsic-size` 等)
- [ ] 画像に明示的な寸法を与え領域を予約。above-the-fold のみ preload、残りは lazy
- [ ] 変異操作 (POST/PATCH/DELETE) は 500ms 未満を目標

## Design / 見た目

- [ ] `:hover`/`:active`/`:focus` は通常状態よりコントラストを上げる
- [ ] 子要素の角丸 ≤ 親の角丸 (同心円を保つ)
- [ ] ボーダー + シャドウを併用 (半透明ボーダーで輪郭を明瞭に)

## Copywriting / コピー

- [ ] 能動態・行動志向。できるだけ少ない語数。固有名詞・用語は一貫させる
- [ ] エラーは前向きに、かつ次の行動を示す ("〜に失敗しました。もう一度お試しください")
- [ ] ラベルは具体的に ("API キーを保存" など。"続行" のような曖昧語を避ける)
- [ ] ユーザー向けメッセージ (トースト/エラー/通知) に内部実装の詳細 (job ID・UUID・ハッシュ) を出さない

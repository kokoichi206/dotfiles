# コード品質原則

- **起こり得ないシナリオに対するエラーハンドリング、フォールバック、バリデーションを追加しない**: 内部コードやフレームワークの保証を信頼する。バリデーションはシステム境界（ユーザー入力、外部API）でのみ行う
- **コメントは Why のみ**: What/How はコードで表現する。説明的コメントは書かない
- **Boy Scout Rule**: 触ったファイル内の小さな問題（数秒で直せるもの）は今修正する。「次のタスクで」に先送りしない
- **スコープクリープを避ける**: 要求されていない機能追加、不要な設定可能化、過剰な抽象化をしない
- **エラーハンドリングは集中化**: try-catch を散らばらせず、上位層で一括処理する

## フォールバック禁止の具体例

| 禁止パターン | 例 | 問題 |
|---|---|---|
| 必須データのフォールバック | `user?.id ?? 'unknown'` | エラー状態で処理が続行される |
| デフォルト引数の悪用 | 全呼び出し元が省略する `function f(x = 'default')` | 値の出処が不明 |
| try-catch で空を返す | `catch { return ''; }` | エラーの握りつぶし |

許容: 外部入力バリデーション時のデフォルト値、設定ファイルのオプショナル値

## 環境

- リポジトリ: ghq 管理（`~/ghq/github.com/owner/repo`）
- Node.js: pnpm（mise 管理）

## 依頼への忠実性

- 求められた行為の「種類」と「範囲」にそのまま応じる。質問には回答を、調査には調査結果と提案を返し、実装は実装を求められたときに行う。行為の種類を勝手に格上げしない。
- 頼まれていないことを「良かれと思って」先回りしない。範囲を勝手に広げるのは暗黙の fallback と同じく、意図しない副作用を生む。
- 何を求められているか不確かなときは、推測で進めず確認する。デフォルトは「勝手に進める」ではなく「問い直す」。

## 問題解決の原則

- **暗黙的な fallback を書かない**: 問題が起きたときに「とりあえず動く」回避策を追加するのではなく、根本原因を特定して解決する
- **修正前に仮説を立てる**: 修正を提案する前に「何が原因だと考えるか」「どのファイル/関数が関係するか」を説明し、承認を得てから実装する

## コード品質原則

- **コントラクト層（API/型）を厳密に定義し、実装層は再生成可能に保つ**
- **静的検査可能なルールは linter で記述する**: CLAUDE.md や会話でなく、その環境の linter に任せる
- **コメントは Why のみ**: What/How はコードで表現する

## フォールバック禁止の具体例

| 禁止パターン | 例 | 問題 |
|---|---|---|
| 必須データのフォールバック | `user?.id ?? 'unknown'` | エラー状態で処理が続行される |
| デフォルト引数の悪用 | 全呼び出し元が省略する `function f(x = 'default')` | 値の出処が不明 |
| try-catch で空を返す | `catch { return ''; }` | エラーの握りつぶし |

許容: 外部入力バリデーション時のデフォルト値、設定ファイルのオプショナル値

# 返信・報告文ドラフト

チャット・メールなど外部に送る文面を下書きする。宛先と媒体のトーンに合わせて整形する。

## 重要: 応答規約とドラフト内容は別

- グローバル設定の「絵文字・派手な表現を使わない」は **Claude からユーザーへの応答**の規約であり、
  **ここでドラフトする文面には適用しない。** 宛先・チャネルのトーンに合わせる（カジュアルな Slack では
  絵文字や「！」を使ってよい。硬い連絡では使わない）。
- この SKILL 本文（Claude の説明）自体は規約どおり絵文字を使わない。区別する。

## 手順

1. **要点を抽出する**
   会話文脈から、相手に伝える/尋ねる要点を洗い出す。

2. **宛先と媒体を推定・確認する**
   誰宛て（顧客 / PM / 社内）で、どの媒体（Chatwork / Slack / メール）かを推定する。不明なら確認する。

3. **媒体に合わせて整形する**
   - **Chatwork**: Markdown 非対応。箇条書きは `・` を使う。素の敬語。
   - **Slack**: 見出しは `【】`、その下に箇条書き。カジュアルな相手なら絵文字・「！」可。
   - **メール**: プレーンテキスト。Markdown 記法（表・`>`・`|`・`#`）を使わない。宛名と署名を付ける。

4. **文面を整える**
   - 簡潔に。冗長な前置き・過剰な配慮・自明な説明を削る（AI 臭を除く）。
   - 文体の詳細規則は humanize-ja スキル（`~/.claude/skills/humanize-ja/SKILL.md`）に従う。
     特にリズム（文末の同形連続・文長の緩急）とクッション言葉 1 つまでの制約。
   - 主語と対象を明示し、指示語だけで受けない。一文で意味が通るようにする。

5. **質問返しは番号を振る**
   相手に複数確認するときは番号付きにして、答えやすくする。

6. **複数案は 3 つ + 推奨**
   トーン違い等で複数案を出すときは 3 案にし、推奨を 1 つ明示する。

7. **ファイルに書き出す**
   長い文面・確定前の下書きは、コピーしやすいようファイルへ書き出す。

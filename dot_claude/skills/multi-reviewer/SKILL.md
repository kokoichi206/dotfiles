# Multi-Reviewer

リポジトリの default ブランチと現在のローカルの差分に対して、複数の AI ツール（codex, gemini cli, coderabbit）を用いて多角的なコードレビューを並列で実行し、その結果から必要性を判断して修正を適用し、最終的なレポートを作成するスキルです。

## フロー詳細

以下の手順に沿って実行してください。

### 1. デフォルトブランチの取得と差分確認

- リポジトリの default ブランチ（例: `main` や `master` など）を取得してください。
- default ブランチと現在のローカル環境の差分を取得してください。

### 2. 利用可能なツールの確認

- 以下の CLI ツールがシステムにインストールされ、実行可能であるかを確認してください。
  - `codex`
  - `gemini`
  - `coderabbit`
- インストールされているツールのみを、次のレビュー工程で使用します。

### 3. 並列レビューの実行

- 各ツールに対して、以下の4つの観点を重点的にレビューするよう指示を出してください。
  1. 一般的なベストプラクティスに沿ったものになっているか
  2. セキュリティ的に問題ないか
  3. パフォーマンスの懸念はないか
  4. リポジトリの設計に反したコードになってないか
- **必須要件:** 複数の観点を一度に問い合わせるのではなく、**各ツール × 各観点 ごとに独立したコマンドとして、すべて並列で実行**してください。これにより、AIがそれぞれの観点に深くフォーカスでき、より精度の高いレビューが可能になります。

**差分の渡し方とコマンドの実行方法:**
差分の渡し方は、各 CLI ツールの仕様に合わせて最適な方法を選択してください。
- **ツール側で差分取得が可能な場合:** ツール自身に `<default-branch>` との差分を計算させる機能（リポジトリ連携機能など）がある場合は、それを優先して利用してください。プロジェクト全体の文脈をより深く理解できる可能性があります。
- **標準入力で渡す場合:** ツール側に差分取得機能がない、または動作が不安定な場合は、確実な方法として `git diff <default-branch> | ...` のように標準入力を活用して差分テキストを渡してください。

**各コマンドのざっくりした使い方（想定例）:**
以下は標準入力で渡す場合の例です。各ツールごとに、以下のようなコマンドを **観点ごとに分けて並列で** 実行します。

- **Codex CLI:**
  `git diff <default-branch> | codex "以下の差分について、【セキュリティの観点】からコードレビューをお願いします。"`
- **Gemini CLI:**
  `git diff <default-branch> | gemini "以下の差分について、【パフォーマンスの観点】からコードレビューをお願いします。"`
- **CodeRabbit CLI:**
  `coderabbit review` など、ツールネイティブのコマンドを使用してレビューをリクエストします。オプション等で特定の観点（例: `--focus security` など）を指定できる場合は、観点ごとに並列実行してください。

### 4. レビュー結果の受け取りと判断

- 各ツールからのレビュー結果が出揃ったら、内容を統合・整理してください。
- それぞれの指摘事項に対して、「修正が必要かどうか（妥当か）」を判断してください。

### 5. 対応（修正）の実行

- ステップ4で「必要」と判断した指摘事項について、該当ファイルに変更を適用（修正）してください。

### 6. 最終レポートの報告

- 最後に、全体的にまとめたレポートをユーザーに報告して完了としてください。レポートには以下を含めてください。
  - 実行したツールとそれぞれの総評
  - 指摘された主要な問題点と、どの観点の指摘か
  - 実際にコードに適用した対応内容
  - 対応を見送った指摘があれば、その理由

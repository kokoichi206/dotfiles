# 会話内容の issue 化

会話中に出た「今はやらないが忘れたくないこと」（未対応アイデア・調査結果・パフォーマンス懸念など）を、
後から会話ログなしで読める形の GitHub issue に起票する。

## 手順

1. **対象と対象リポを特定する**
   - 直前の会話から issue にする内容を特定する。論点が複数混ざっているなら issue を分ける（1 issue 1 論点）。
   - 起票先はカレントの会話が対象にしているリポジトリ。別リポの話題が混ざっていて確信が持てないときは確認する。

2. **重複を確認する**

   ```bash
   gh issue list --search "<キーワード>" --state all --limit 20
   ```

   - 既存 issue があれば新規に作らず、既存へのコメント追記を提案する。

3. **定型フォーマットで本文を組む**
   - 会話の文脈を知らない読み手（未来の自分）が読んで理解できることが条件。
     指示語（「さっきの件」「これ」）で受けず、対象を明示する。

   ```markdown
   ## 背景

   （なぜこれが必要になったか。1〜3 行）

   ## 現状の根拠

   （観測した事実。ログ・エラー文・ファイルパス・PR / commit リンクなど、後から検証できる形で）

   ## 提案 / 未決事項

   （やるべきこと、または決めきれていない選択肢）
   ```

   - 秘密情報（メールアドレス・金額・トークン）を本文に書かない。private リポでも直書きせず参照で書く。

4. **起票する**

   ```bash
   gh issue create --assignee @me --title "<動詞で始まる具体的なタイトル>" --body "<本文>"
   ```

5. **URL を報告する**
   - 作成した issue の URL を提示して終える。複数作った場合は一覧で出す。

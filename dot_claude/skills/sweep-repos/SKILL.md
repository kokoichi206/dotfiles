# ghq 横断アップグレードキャンペーン

依存ライブラリのメジャーアップグレードなど、同一の変更を ghq 配下の複数リポジトリへ
横断適用する。「対象一覧 → 除外確認 → 並列適用 → PR リンク一覧」を 1 セットの契約として実行する。

## 手順

1. **対象リポジトリを列挙し、着手前に除外確認を取る**
   - `ghq list` から対象条件（例: 該当依存を持つ package.json がある）でリポを絞り込む。

     ```bash
     for r in $(ghq list -p); do
       # 対象判定の例: 依存に <pkg> を持つ
       rg -q '"<pkg>"' "$r/package.json" 2>/dev/null && echo "$r"
     done
     ```

   - 絞り込んだ一覧を提示し、**「この一覧で着手してよいか・除外するリポはないか」の回答を得るまで作業を始めない**。
     アーカイブ済み・fork・実験リポなどユーザーしか判断できない除外対象が毎回ある。

2. **リポごとに並列で適用する**
   - リポ単位で独立しているので、worktree + subagent で並列化する。1 リポ 1 エージェント。
   - 各エージェントへの指示に含めること:
     - `git fetch origin` 後、default branch から作業ブランチを切る
     - 変更適用後、そのリポの検証手段（build / test / lint）を実行する
     - 途中でユーザーから除外指示が来たリポは即中断し「除外」として記録する

3. **リポごとに PR を作成する**
   - `gh pr create --assignee @me`。PR 本文には変更内容と検証結果を書く。
   - **マージはしない**（自律マージ禁止。CI green でも「マージ可能」と報告して止まる）。

4. **最終出力に PR リンク一覧を必ず含める**
   - 成功: `リポ名 → PR URL` の一覧。
   - 失敗・スキップ: `リポ名 → 理由`（ビルド不能、対象外だった、ユーザー指示で除外、など）の一覧。
   - 「対象として列挙した全リポ」がどちらかの一覧に必ず現れること（漏れを作らない）。

# Orca automation 登録

CLI のコマンド体系は orca-cli スキルに従う。この skill は「何をどう登録するか」の設計を定める。

## 登録プロンプトに必ず入れる 5 点

1. **日付窓**: 「直近 N 日」の相対指定にする。実行日に依存する絶対日付を書かない。
2. **対象**: リポジトリ・ディレクトリを絶対パスで特定する。
3. **出力先**: 成果物のパスと命名を実行先リポ基準で確定する。実行のたびに置き場所が変わる書き方をしない。
4. **停止境界**: 調査のみ / 提案まで / issue 起票まで / PR 作成まで、のどこで止まるかを明記する。
   マージは境界に含めない（自律マージ禁止）。
5. **失敗の可視化**: 無人実行では会話上の報告が読まれない。成否・件数をログファイルへ追記する
   手順をプロンプトに含める（next-todo-mail の SUCCESS/FAILURE 行方式）。

## クロスモデル 3 ステージ構成（品質を上げたい定期レポート向け）

日付窓をずらした 3 本の automation に分けて登録する:

1. claude がレポート生成
2. 翌日: codex が同観点で再生成して突合し、修正・削除を同一コミットに積む
3. 翌々日: 承認済み項目だけを実装（起票・PR は停止境界の指定に従う）

## 登録前の確認

- 既存 automation の一覧を出し、同種の登録がないか確認する（二重登録の実績がある）。
- 登録コマンドはまずユーザーに提示する。実行まで任されている場合のみ実行する。

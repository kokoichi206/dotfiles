# UI モックアップ比較

見た目・レイアウト・文言・設計方針を決める前に、複数案を **自己完結 HTML** で可視化し、
比較してから 1 つに絞る。実装はユーザーが案を選んでから着手する。

## 原則

- **実装より先にモックで方向性を合わせる。** いきなり本実装に入らない。
- **各案は自己完結の 1 HTML ファイル。** CSS/JS はインライン、外部依存なし。単体で `open` すれば見える状態にする。
- 選択状態・ホバー・展開/折りたたみなど、判断に必要な簡易動作は入れる。
- 設計案（UI でなくロジック/構成の選択）なら、案を並べた**比較表 HTML** にする。

## 手順

1. **現状を把握する**
   対象画面・既存コンポーネント・制約（フレームワーク、既存トークン、余白/色の慣習）を確認する。

2. **2〜4 案を自己完結 HTML で作る**
   案ごとに 1 ファイル。狙いを変えた別案にする（似た案を並べない）。

3. **比較ギャラリーを 1 枚にまとめる**
   全案を 1 ページで見比べられる HTML を作る（`<iframe>` で各案を並べる、またはカードで横並び）。

   ```bash
   open <ギャラリー.html>
   ```

4. **各案の狙いとおすすめを示す**
   案ごとに狙いを 1 行で説明し、**おすすめを 1 つ**明示する（「一旦」で濁さない）。

5. **承認後に実装する**
   ユーザーが選んだ案だけを本実装に落とす。

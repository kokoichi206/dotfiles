# 要望ごとの PR 分割

顧客要望・タスクの箇条書きを貼られて「要望ごとに」「それぞれ PR」と言われたときの定型。
1 要望 = 1 PR に分け、着手前に方針を擦り合わせる。

## 手順

### フェーズ1: 整理と擦り合わせ（実装前）

1. **要望を列挙・採番する**
   貼られた内容を項目に分解し、番号を振る。曖昧な項目は推測で埋めず「要確認」として残す。

2. **件数を提示する**
   「全 N 件」と件数を先に示す。

3. **各項目に見立てを付ける**
   項目ごとに以下を 1 行で示す。
   - 対応可否（対応可 / 要確認 / 対応不可とその理由）
   - 種別（feat / fix / chore など）
   - 変更箇所の見当（ファイル・関数レベル）

4. **承認を得る**
   この一覧を提示し、着手してよいか確認する。承認前に実装を始めない。

### フェーズ2: 項目ごとに PR 化

5. **項目ごとに独立ブランチを切る**
   - 各項目は base（repo 規約 → 無ければ default branch）から独立したブランチで作業する。
   - 並行して進めるなら worktree を使い、作業を混在させない。

     ```bash
     git fetch origin
     git worktree add <path>/<feat/項目> -b <feat/項目> origin/<base>
     ```

6. **項目ごとに個別 PR を作る**
   - 1 要望の変更だけを含める。無関係な差分・一時ファイルを混ぜない。
   - PR タイトルは英語、本文は日本語。

7. **一覧と CI を報告する**
   - 「項目 | PR URL | CI 状態」の対応表で報告する。CI は `--watch` で占有せずポーリングで確認する。
   - マージはユーザーの明示承認を待つ（自律マージしない）。

# Review Loop

変更差分に対するレビューを「発見パス」と「検証パス」に分離して実行する。
検証パス（敵対的検証）で反証されなかった指摘だけを修正対象とすることで、
もっともらしいが誤った指摘（plausible-but-wrong）の混入と、
修正者自身による指摘の握りつぶしの両方を防ぐ。

## 原則

- **発見と検証と修正は別の主体が行う**。検証 subagent には発見者の推論・会話の経緯を渡さず、指摘文と該当コードだけを渡す。
- **失敗シナリオのない指摘は bug として扱わない**。「この入力・状態でこの誤動作が起きる」を書けない指摘は品質提案に降格する。
- **収束 = 確定指摘ゼロ**。レビュアーが指摘をやめたことではなく、検証を通過する指摘が出なくなったことを収束条件とする。

## フロー

### 1. 対象差分の確定

- 対象を一意化する: PR 番号指定なら `gh pr diff <番号>`、未指定なら default ブランチと現在のローカルの差分。
- 差分をファイルに保存し、以降の全パスで同一の差分を参照する。

### 2. 発見パス（並列）

以下のレビュアーを並列で実行する。

- **Claude subagent（必須）**: general-purpose subagent に差分・リポジトリ規約（CLAUDE.md / rules）のみを渡す。実装の経緯・会話の文脈は渡さない。指示は「この差分が壊れる具体的な再現手順（入力・状態 → 誤動作）を構築せよ。構築できない懸念は quality 提案として分けて報告せよ」。
- **codex CLI（あれば）**: codex スキルの呼び出し方に従い、外部モデル視点のレビューを 1 枠追加する。

各指摘は次の形式に正規化する:

```
- 対象: <file:line>
- 主張: <1 文>
- 失敗シナリオ: <入力・状態 → 誤動作>（書けなければ quality 提案へ降格）
```

### 3. 検証パス（敵対的検証・並列）

失敗シナリオ付きの指摘 1 件ごとに、独立した subagent を並列で起動する。

- 渡すもの: 指摘（対象・主張・失敗シナリオ）と該当コードのみ。発見者の推論やラウンドの経緯は渡さない。
- 指示: 「この指摘を反証せよ。コードを読み、失敗シナリオが実際には成立しないことを示せ。**確信を持って成立すると確認できた場合のみ CONFIRMED、それ以外は REFUTED**」
- REFUTED の指摘は棄却する。棄却理由は最終レポートに残す。

### 4. 修正

- CONFIRMED の指摘のみ修正を適用する。
- quality 提案は列挙にとどめ、軽微なもの（typo・明白な冗長）以外は勝手に直さずユーザー判断に回す。

### 5. 再レビュー（ループ）

- 修正後の差分に対して 2〜4 を繰り返す。
- 収束条件: 発見パスの指摘が全件 REFUTED または quality 降格になったラウンドで終了。
- 上限 5 ラウンド。上限到達時は残った CONFIRMED 指摘を列挙してユーザーに判断を仰ぐ。

### 6. 完了報告と接続

- レポートに含める: ラウンド数 / 指摘の総数と内訳（CONFIRMED・REFUTED・quality 降格）/ 適用した修正 / 見送りと理由。
- ユーザーが PR 作成まで求めている場合は pr スキル（または対象リポの create-pr 手順）へ接続する。求められていなければ報告で止める。

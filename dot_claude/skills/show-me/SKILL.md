# show-me

HumanLayer の [show-me](https://github.com/humanlayer/skills/blob/6ab9013a10c28f5046f7f999549cd5328a0b30d7/plugins/show-me/skills/show-me/SKILL.md) を個人向けに変更したもの。ライセンスは [LICENSE](LICENSE)。

今の質問を理解・判断するための、最小限で十分な図を作る。説明対象によって形式を選ぶという上流の方針を保ち、関係の正確さと後から読み返せる根拠を加える。

## 何を見せるか

会話から「何を理解・比較したいか」「誰が読むか」「対象の範囲」を拾う。明示済みの条件は聞き直さない。

| 知りたいこと | 見せ方 |
| --- | --- |
| 呼び出し順や責務 | 短い呼び出しツリー、コンポーネントツリー |
| コードやファイル構成の変更点 | 必要な前後差分 |
| DB の変更・データ移行 | 対象を絞った ER 図と変更前後、移行の有無・対象 |
| 認証・状態・条件による挙動 | シーケンス図や分岐図。質問で挙がった分岐を対応づける |
| ネットワーク・データ連携 | 境界を囲み、配置場所と接続方向、運ばれるものを描く |
| 設計案の選択 | 同じ粒度の比較図と、判断軸・利点・欠点・移行への影響 |
| 複数の図や短文を並べて読みたい | 直接ブラウザで開ける HTML |

GitHub の issue などで Mermaid を指定されたら、その形式を守る。短い表や差分で足りる説明を無理に図にしない。非エンジニア向けでも、接続条件や所有関係を比喩で消さない。

## 描く前の根拠

- 実装の説明はコード・DDL・設定を読む。会話ログは依頼や決定の根拠として扱い、過去の説明を現在の実装だと断定しない。
- 各接続について始点、終点、方向、関係の意味、確認元を特定する。「関連する」だけの矢印は描かない。
- 社内ネットワーク、端末、クラウドなどの境界を先に配置する。隣接配置だけで所属や接続を暗示しない。
- 現状、提案、未確認をラベルで区別する。未回答の条件は「未確認」として残す。既知の正常系や質問された分岐を落とさず、根拠のない異常系を追加しない。
- 比較図は対象名・粒度・配置をできるだけ揃え、差がある部分を強調する。会話内の「C 案」だけを名前にせず、内容を表す名前を付ける。

## HTML の作り方

- 日本語で簡潔に書き、日本語と半角英数字の間に半角スペースを入れる。識別子・パス・コードの内部は変更しない。
- 原則として HTML 1 ファイルに CSS とインライン SVG を含め、外部 CDN やフォント取得なしで開けるようにする。編集可能な構造を保つ。
- 明るい無彩色の背景と読みやすいシステムフォントを基本に、意味のある差だけにアクセントを使う。指定の製品や既存文書の見た目がある場合はそれに合わせる。
- タイトルの次に、答えとなる短文と図を置く。根拠・補足は図の近くか折りたたみに置く。
- SVG に `viewBox`、`role="img"`、固有 ID の `title` / `desc` を付ける。矢印の始点・終点を対象の枠へ接続し、ラベルと線、別の箱が重ならないようにする。
- スマホでは比較欄を縦に並べる。大きな図は縮小して読めなくするより、全体図と詳細図へ分ける。
- 操作を加えるなら、比較や理解に必要なものだけにする。切り替え前の静止状態でも主題が読めるようにする。

## 保存と提示

- 保存先の指定や既存の文書規約があれば従う。
- 指定のない一時的な HTML は `~/.cache/show-me/YYYY-MM-DD/<topic>/index.html` に作る。同日に同じ対象の出力があれば、同じ図の更新か別案かを確認して上書きを避ける。
- 再利用できる知識や後から見返しそうな説明・図解・調査結果を作ったら、保存指示を待たず [references/retention.md](references/retention.md) に従って自動保存する。書庫への登録やタグ整理でも同参照を読む。既定のローカル書庫は `~/visual-notes/`。タグの追加・別名管理・統合は、同参照の基準に沿ってエージェントが進めてよい。
- 出力後、利用可能なブラウザで実物を確認する。接続先、矢印方向、文字の重なり、広い画面・狭い画面、追加した操作を確認し、不備を直す。確認できなかった範囲はそのまま伝える。
- 最後に成果物のリンクと要点を返す。ユーザーが表示を求めていれば、ローカルで開く。HTML の作成は公開・アップロードの許可を含まない。

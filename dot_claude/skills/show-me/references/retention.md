# 後から読み返す図解

## 残す対象

汎用的な知識、長く使える知識、後から見返す可能性がある説明・図解・調査結果は、ユーザーの「残して」を待たずに自動保存する。保存候補の提示や確認だけで止めず、HTML の作成・登録・タグ付け・一覧の再生成まで完了する。明示的な「保存しない」の指定は優先する。

- 設計判断と、採用・不採用の理由。
- 後で再確認するシステム構成、認証・ネットワークの境界。
- 変更前後と移行手順。障害の原因と修正を確かめた記録。
- 別の仕事でも参照する概念や調査の要点。

短い説明でも再利用性があれば、必要な内容だけの HTML として残す。図や長文を足して水増ししない。保存したリンクを最終報告に短く添える。同じ題材の既存資料があれば更新を優先する。

その場の操作確認、未選択の見た目だけの案、毎回生成される進捗表示は、一時出力のままでよい。未確定の設計も残せるが、決定済みとは区別する。

## 保存時に残す情報

HTML の見える箇所に題名、要点、作成日・内容の更新日、対象、確認時点、状態（検討中・採用・参考・廃止）を付ける。
根拠は関連するコードの commit とパス、issue・資料の URL、必要なら会話の session ID。生ログや認証情報を貼り付けない。

同じ題材の補足は同じ文書を更新する。独立した判断は別文書にして関連リンクを張る。コードの根拠が古くなっても、確認せずに「最新」と書き換えない。

## ローカル書庫

2026-09-07 にローカル利用と、エージェントによるタグの追加・管理が認められた。既定は `~/visual-notes/`。自動保存もユーザーが許可済みなので、都度の確認は不要。

- `catalog.json`: 全リポジトリ共通の文書とタグの唯一の正本。リポジトリごとのタグ台帳は作らず、一覧は必ずここから生成する。`catalog.previous.json` は直前の変更前の控え。
- `items/<文書 ID>/index.html`: 書庫に保存した HTML。元が一時 worktree でも残る。
- `index.html`: カタログと本文から再生成する閲覧用 HTML。直接開ける。検索条件は URL のフラグメントに残る。
- 別名も検索対象。複数タグの AND / OR、プロジェクト、文書状態で絞り込める。

生成コードはこのスキルの `scripts/library.py` と `assets/library.html`。生成した `index.html` や埋め込まれたタグを手で編集せず、下のコマンドで更新する。

既存の資料置き場にある文書は `--reference` で参照登録できる。その場合、原本の編集後に `build` すると本文索引が更新される。参照元を削除すると開けなくなるため、一時 worktree の資料には使わない。

コピー登録は単体で開ける HTML に使う。相対パスの画像・CSS などが必要なら、先にそれらを含む単体 HTML を用意するか、永続リポジトリの原本を参照登録する。文書の作成日・内容の確認時点は HTML 内に残し、書庫の登録・更新日時で代用しない。

## タグを増やしすぎないための基準

エージェントは毎回の追加・整理をユーザーへ聞き直さず、次の順で判断する。

1. `tags` で正式名、別名、説明を読む。ID・大文字小文字・全角半角・空白・ハイフンの違いは既存タグへ解決される。
2. 文書の主題を検索するために有用なタグを選ぶ。通常は 2〜5 個が目安で、数合わせはしない。本文に一度出るだけの製品名を全部タグにしない。
3. 同じ概念の略語・訳語・表記違いなら `tag-alias` にする。例: `AI Agent` / `AI エージェント`。関連するだけの別概念（認証 / 認可）は統合しない。
4. 新しい概念なら、既存タグでは足りない理由を確認して `tag-add` する。「何を含めるタグか」を説明へ書く。日付・検討中などは専用項目を使う。リポジトリ名はユーザー指定により、プロジェクト項目に加えてタグにも付ける。
5. 新設や統合の前後に `audit` で使用件数を確認する。未使用・1 件だけのタグは見直すが、それだけを理由に削除や一般化をしない。タグ数の上限を満たすために意味の異なるタグをまとめない。
6. 重複が確認できたら `tag-merge` する。全資料の参照を移し、古い ID と名前を別名として残す。別名を含む名前の重複は CLI が拒否する。意味の同一性はエージェントが説明と対象資料から判断する。

一覧の『タグ台帳・整理の目安』で、ユーザーも正式名・説明・別名・件数を確認できる。タグ数の変化を隠さず、まとめて整理した際は追加・統合した内容を短く報告する。

## 発動元のリポジトリタグ

リポジトリ内の作業でこのスキルを使ったら、内容が汎用知識でも発動元のリポジトリ名をタグに含める。

- 作業対象の `git remote get-url origin` や既存の Git 設定から `owner/repository` を確かめる。一時 worktree のディレクトリ名や図解中に登場した別プロダクト名を発動元として扱わない。
- `add` に `--repository owner/repository` を渡す。CLI が中央台帳にリポジトリタグを作成・再利用し、自動付与する。`--project` も通常は同じ値にする。
- 表示名はリポジトリ名。同名が他の所有者や既存の概念タグと衝突した場合は `owner/repository` で区別する。ID と所属情報は表示名から独立して保持する。
- リポジトリ外の知識は `--repository` を付けず、分野を `--project` に指定する。所有者が未確認なら Git 設定を調べ、推測で別リポジトリを登録しない。
- `retag` でも発動元のリポジトリタグを維持する。リポジトリタグを一般概念の別名として統合しない。

## コマンド

以下では `LIBRARY` をこのスキルのスクリプトへの絶対パスとしている。Claude / Codex とも同じファイルを使う。

```bash
LIBRARY="$HOME/.claude/skills/show-me/scripts/library.py"
python3 "$LIBRARY" tags
python3 "$LIBRARY" audit
python3 "$LIBRARY" tag-add authentication 認証 --alias Authentication --description 'ログインや本人確認の仕組み。操作の許可判定である認可は含めない。'
python3 "$LIBRARY" tag-alias authentication ログイン
python3 "$LIBRARY" add /absolute/path/auth-flow.html --title 'ログイン時の認証フロー' --summary '認証の分岐と確認元をまとめた資料。' --project owner/repository --repository owner/repository --tag 認証 --status 検討中
python3 "$LIBRARY" list
python3 "$LIBRARY" build
open "$HOME/visual-notes/index.html"
```

`add` は既定で書庫へ HTML をコピーする。永続リポジトリを参照するときだけ `--reference` を付ける。同じソースパスの再登録は同じ文書を更新する。元の場所が変わった文書は `--id <既存の文書 ID>` を指定して重複を避ける。

既存文書のタグだけを変える場合は `retag <文書 ID> <タグ>...`、表示名変更は `tag-rename <タグ> <新しい正式名>`。ID は変えず、旧名を別名として残す。

```bash
python3 "$LIBRARY" tag-merge <統合元のタグ> <残すタグ>
```

書き込みコマンドはカタログを更新し、一覧も再生成する。複数セッションの更新はロックで直列化する。`build` が参照ファイルの欠落で失敗した場合は、原本を復元するか正しいファイルを `--id` で登録し直す。黙って索引から除かない。

元の資料を置き換えたり、外部へ同期・公開したりする処理は含まない。まずローカルで運用する。

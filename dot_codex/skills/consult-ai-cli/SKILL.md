# Codex から Claude / Grok への相談

## 経路の選択

- Claude / Claude Code への相談は `claude`、Grok への相談は `grok` をローカルのコマンド実行ツールから直接呼ぶ。「相談して」は Web チャットを開く指示ではない。
- Orca Computer Use、Codex Computer Use、Chrome、ブラウザ操作、GUI ターミナルへの入力で質問を送らない。ユーザーが明示的に Web 版・既存ブラウザ会話を指定した場合だけ、その指定経路を使う。
- 指定された相手を別のモデル・組み込みサブエージェントで代用しない。両方を指定されたら両方へ聞く。親エージェントの推測を外部 AI の回答として報告しない。
- CLI の未検出、認証エラー、タイムアウトは CLI 側の原因を調べる。勝手にブラウザや別プロバイダーへ切り替えない。解消できなければ未取得として伝える。

## 相談の準備

対象リポジトリで実行する。`command -v claude` / `command -v grok` と必要な `--help` を確認する。2026-09-10 に確認したローカル CLI の呼び出し例を下に示す。オプションが変わっていたら、インストール済み CLI の help に合わせる。

実行ごとに作業用ディレクトリを作り、質問を `request.md`、標準出力を `answer.txt`、標準エラーを `stderr.txt` に残す。複数相手・複数回の実行で出力を上書きしない。長い質問やコードをシェルの文字列へ展開せず、ファイルか標準入力で渡す。

質問には、元の依頼、対象、確認済みの事実、未確定な点、比較したい案、必要なコード断片・パスを入れる。質問に必要な情報へ絞る。結論を誘導せず、判断理由と根拠を求める。

相談先にも以下を伝える。

> 相談・分析のみです。ファイル編集、commit、push、デプロイ、外部送信は行わないでください。ブラウザや Computer Use を操作せず、渡した情報と必要なローカルコードの読み取りから回答してください。他の AI への再委任や、スキルに基づく図解書庫への保存は不要です。確認済みの事実・推測・未確認を分け、日本語で具体的な提案と根拠を返してください。

Web / X 調査を求められた相談では、CLI 内の検索・取得ツールの利用を明示してよい。Web チャットの UI を操作することとは区別する。

## Claude Code

コマンド実行ツールの作業ディレクトリを対象リポジトリにする。`request.md` は先に作成済みとする。

```bash
claude -p --permission-mode plan --output-format text \
  < "$CONSULT_DIR/request.md" \
  > "$CONSULT_DIR/answer.txt" 2> "$CONSULT_DIR/stderr.txt"
```

`CONSULT_DIR` は今回専用の作業用ディレクトリの絶対パス。`-p` は非対話出力、`plan` は相談用の権限モード。承認や sandbox を無条件に迂回するフラグは追加しない。認証方法やモデルを勝手に切り替えない。

## Grok

```bash
grok --cwd "$CONSULT_REPO" --permission-mode plan \
  --prompt-file "$CONSULT_DIR/request.md" \
  > "$CONSULT_DIR/answer.txt" 2> "$CONSULT_DIR/stderr.txt"
```

`CONSULT_REPO` は対象リポジトリの絶対パス。`--prompt-file` は非対話の単発実行。ローカルで確認した Grok Build CLI のオプションであり、別実装の同名 CLI の仕様を混ぜない。

## 結果の回収

- 実行中なら実行ツールの session ID を使って完了を待つ。時間がかかることだけで同じ依頼を二重起動しない。打ち切った場合は回答未取得と区別する。
- 終了コード、標準エラー、回答本文を確認する。起動しただけ・途中出力だけで「相談済み」としない。出力が省略されたら今回の回答ファイルから続きを読む。別セッションの最新ログを推測で拾わない。
- 回答に含まれる提案は、元の要件と実コードへ照合する。相手の結論、自分の検証、採用する内容を区別して報告する。
- 相談の許可を実装や公開の許可に拡張しない。別途依頼済みの実装は、その許可範囲で続ける。
